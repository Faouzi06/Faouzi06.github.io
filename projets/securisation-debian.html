01Contexte et objectifs

Deux ateliers enchaînés : d'abord cartographier la surface d'attaque d'une VM Debian et d'une VM Windows, juste après leur démarrage, pour obtenir une ligne de base. Ensuite, consolider le socle Linux et mesurer objectivement le progrès.

03Étapes de consolidation

  1. Diagnostic Lynis

    Audit de référence avant toute modification : indice de durcissement de 63/100.

  2. SSH par clé uniquement

    Génération d'une paire de clés Ed25519 renforcée, déploiement avec ssh-copy-id, puis désactivation de l'authentification par mot de passe. Cinq connexions avec des comptes fictifs ont été tentées : toutes sont rejetées avec Permission denied (publickey).

    Bash · clé SSH
    ssh-keygen -t ed25519 -a 100 -C "admin-tp"
ssh-copy-id -i ~/.ssh/id_ed25519.pub admin@192.168.56.2

# Test : connexions refusées sans clé valide
for i in {1..5}; do ssh fauxuser$i@192.168.56.2; done
  3. Défense active : Fail2ban

    Une prison dédiée à sshd bannit automatiquement une adresse après des échecs répétés. Contrôle à froid, puis échecs provoqués : on passe de 0 à 5 échecs comptabilisés, et l'IP de test apparaît dans la liste des bannies.

    Bash · Fail2ban
    sudo systemctl restart fail2ban
sudo fail2ban-client status sshd       # Total failed: 5 · Banned IP list: 192.168.56.1
sudo fail2ban-client set sshd unbanip 192.168.56.1
  4. Cloisonnement réseau : UFW

    Principe du moindre privilège : tout le trafic entrant est refusé par défaut, et le SSH reste la seule exception pour l'administration à distance.

    Bash · UFW
    sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw enable
  5. AppArmor et réduction des services

    aa-status confirme 121 profils chargés, tous en mode enforce. Les services inutiles pour un serveur (CUPS pour l'impression, Avahi pour la découverte réseau) sont désactivés puis masqués, pour qu'ils ne puissent pas être réactivés par erreur.

    Bash · services
    sudo aa-status
sudo systemctl disable --now cups.service avahi-daemon.service
sudo systemctl mask cups.service avahi-daemon.service
sudo ss -tulpn                         # seul le port 22/tcp reste en écoute

04Points clés

Constat

systemctl disable ne suffisait pas : les sockets cups.socket et avahi-daemon.socket pouvaient relancer les services.

Solution

systemctl mask lie les unités à /dev/null, puis ss -tulpn vérifie qu'aucun port n'est resté ouvert.

Risque

Couper l'authentification par mot de passe ou activer UFW sans exception peut bloquer l'administrateur hors de la machine.

Solution

La clé est testée avant de désactiver les mots de passe, et la règle ufw allow ssh est posée avant ufw enable.
